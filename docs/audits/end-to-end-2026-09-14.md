# Admin/client reliability pass — 2026-09-14

Implemented on master, desktop 1.4.3. This pass reviewed the admin/API command boundary, fleet organization and rendering, desktop native status synchronization, engine identity and existing regression coverage. It does not certify every production environment.

## Repairs

- **Delayed status replies overwrote newer control outcomes.** Poll requests now capture each process's lifecycle revision. Start, Stop, maintenance, error/exit events and output from a new process run invalidate older requests. Reconciliation ignores a reply when newer lifecycle state exists or an operation is still pending.
- **Automatic restart observations could be discarded or mixed with an old run.** Parsed observations carry their native run identity. Reconciliation preserves matching fresh output; a new run clears old rates, counters, pool state, pause state and version. Logs remain bounded through the existing console/network queues. Stopped snapshots still clear active observations.
- **GPU inventory failure prevented Stop.** GPU inventory is now required for Start, Restart and Enable, while scoped Stop, Disable, configuration delivery and maintenance remain available subject to existing access, connection and capability checks. A missing inventory does not establish that an already-owned GPU process stopped.
- **Stop command receipts fell back to legacy engine names.** Idle results now use the selected engine, consistent with stopped telemetry; running results retain the actual engine. This covers SRBMiner in both legacy slots.
- **Organization and fleet efficiency.** General rig search includes group names, consistently across fleet rows, summaries, history and incident selection. Fleet decoration builds incident/command maps once rather than scanning every matching incident/command for every rig. Full fleet retrieval still occurs; this is not a claim of database-level pagination or distributed scaling.
- **Large-rate display.** Admin rates include TH/s and PH/s for high-rate algorithms. Negative, nonnumeric and missing rates remain unavailable; zero remains zero. Storage/API units remain H/s and unlike algorithms remain separate.

Real pool acceptance, algorithm/GPU performance, quarantine behavior and installed Windows/Linux update flows remain hardware/operator validation items from the [SRBMiner audit](client-2026-09-13/srbminer.md).
