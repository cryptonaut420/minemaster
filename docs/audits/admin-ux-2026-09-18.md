# Admin UX repair — September 18, 2026

## Baseline and cause

Compared the last pre-audit admin (`093c6c8`) with the September 13 overhaul and September 15 control repair. The earlier version put GPU/CPU totals, a filled history chart and per-rig rates/hardware in the ordinary dashboard view. The newer interface hid performance behind a collapsed section, made hardware optional, exposed Play and Pause simultaneously, and left terminal command receipts and full startup logs in table rows. Passing protocol tests did not make these design regressions acceptable.

## Implemented

- Restored a charcoal dashboard with large cyan GPU and lavender CPU totals and prominent per-rig rates. Backend algorithm-specific calculations remain authoritative; unlike algorithms are never added together.
- Restored always-visible hash history above the table, with scope/algorithm tabs, period selection, missing-data gaps and coverage on hover. Filtered totals/history are labeled and include all matching pages.
- Hardware, temperatures, load, GPU power and RAM usage are always visible in each table row or narrow-screen card. Sensor identity and observation freshness are preserved; zero is shown as zero, missing is a dash.
- Replaced duplicate row buttons with one state-dependent Play/Pause control. Running processes and retries keep Pause; pending preparation permits Cancel start. Offline controls are disabled. Long errors are summarized with links to full details. Old successful receipts no longer occupy rows.
- Kept whole-fleet and selected-rig controls, default mining/online-first sorting, filters, saved views, advanced commands, monitoring, logs and API access. Selected Play resolves current rig state before choosing scope; already running scopes are skipped. Stop continues to cover ALL scopes.
- Reconnected the old toast UI to the active admin. Quick actions show progress and receipt-based success/failure, including partial failures. Toasts are dismissible, bounded to four and survive ordinary polling renders without their dismissal timer resetting. Saves/API-key changes also have toast feedback; dispatch-only operations never claim execution success.
- Rig details receive focus and scroll into view when opened. Narrow-screen cards keep core statistics and controls accessible. Outages retain the last snapshot with an explicit warning and disable affected quick controls.

- Browser verification used loopback-only disposable MongoDB and 12 simulated agents, including an offline rig, an overdue agent, zero hashrate, a hot CPU, stale CPU temperature and a long startup error. No mining binary, installer or production command was executed.
- Checked desktop at 1440 × 1050 and a measured 390 × 900 viewport. Narrow layout had no document/table horizontal overflow; toast bounds stayed inside the viewport. GPU and CPU history switched correctly, including the last-hour period. Old startup logs no longer expanded ordinary rows.
- Exercised row Pause → Play, Play → Pause, selection Pause/Play using the same selection, whole-fleet Pause/Play, and a synthetic command rejection. Progress and terminal toasts were observed; failure retained the real mining state and persistent command error. Simulated backend outage disabled controls while retaining the last snapshot.
