# KRig integration and trial — October 3, 2026

## Scope

Added KRig as an explicitly selected GPU engine for Quantus and Pearl. Existing CPU and GPU assignments stay unchanged. This is an engine integration, not a claim that Windows Security permits the binary or that the fleet has switched.

The initial review found upstream 1.5.5, but the release freshness check identified **1.5.6**, published October 3 with support for new Kryptex pool regions. Both official Windows/Linux x64 archives were downloaded and matched GitHub's published SHA-256 digests; their individual executable hashes are pinned in the release manifest. No mining executable or installer was executed during verification. Archives contain only the executable and example launcher; the launcher is excluded. Upstream redistribution permission is retained with packaged app notices.

## Implementation

- Matching client/server catalogs, GPU-only algorithms, strict shared option behavior and CPU rejection. Engine switches clear stale custom paths, legacy indices and tuning. KRig algorithm selection also updates the coin label.
- Admin/client selectors, named saved profiles, existing scoped commands, capability-gated assignment delivery, API catalog and engine identity. Older clients cannot receive/start unsupported KRig configurations. No global profile activation.
- Foreground native ownership, separate working directory, original executable names, file logging, verified repair, and existing cancellation/recovery budgets. GPU Stop leaves CPU mining running.
- Native loopback-only `/hiveos` polling every ten seconds with bounded timeout/response size. Process-level `khs` converts to H/s; optional share counters and version retain observation time. Uptime/algorithm checks reject mismatched, frozen or old-run responses. Exit/Stop cancels requests and discards late replies. API failure does not stop mining or invent zero. File logs remain the diagnostic source, not a second hashrate source.
- No arbitrary arguments, CPU backend, per-GPU assignments, automatic clock changes, OS protection changes or automatic quarantine restoration added. Linux AMD HIP runtime installation remains an operator prerequisite.

## Verification

- 145 client tests pass, including KRig scope/validation parity, Windows/Linux launch specifications using inert files, transport/failover/worker arguments, platform rejection, exact units/zero/missing samples, failed/frozen/API responses, late callback cancellation, GPU Stop and independent CPU state.
- 143 server tests pass using disposable MongoDB and synthetic agents, including KRig delivery capability gates, reconnect assignment, scoped acknowledgments/failures and telemetry identity/shares.
- Client and admin production builds pass.
- Loopback browser fixtures exercised KRig Quantus and Pearl selection, admin saves and outage feedback, client simulated hashrate/share display and Stop, invalid-pool feedback, and ARM64 exclusion. Desktop and 390px layouts inspected; both measured 390px document width on a 390px viewport. No live rig was used for these tests.
- Upstream HiveOS integration documents `/hiveos`, `khs` and `stats`; tests use the conventional HiveOS nested fields. Actual Windows endpoint shape, accepted-share accounting, driver compatibility and overnight stability still require the trial. Unexpected shapes stay unavailable with diagnostics.

## Trial/release status

Candidate desktop version: **1.4.16**. Intended publication is a prerelease, keeping the stable automatic-update target on 1.4.15. Install on one trial rig before considering wider adoption. GPU settings can then be delivered using a saved profile's selected-rig action without changing CPU settings or global fleet defaults.

At the read-only production check, PG_Z6 was offline; AAGZ-PG-FrontDesk remained online. No production start/stop/repair/install command was sent during implementation. The first Windows trial is pending candidate installation and an available rig.
