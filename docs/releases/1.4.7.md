# MineMaster 1.4.7

- Fix SRBMiner telemetry when redirected console output is absent: CPU/GPU processes have separate owned file logs, preserving original observation times and bounded cleanup.
- Parse SRBMiner file version, pool connection, aggregate accepted/rejected share counters and PH/s units.
- Respect SRBMiner's 90-second aggregate reporting cadence with a 120-second rate freshness limit; stale agent/sensor data still expires after 60 seconds. Unlike algorithms remain separate.
- Existing Windows/Linux update safeguards, saved mining intent, version-bound install checks and managed miner verification are retained. Mining engines remain pinned to their previously verified versions.

Matching admin deployment adds visible coin-profile cards and fleet activation, a client version/update overview, and backend-owned daily profitability alerts. This release does not automatically switch coins.

Validated with client regression tests, backend regressions, production builds and an explicitly authorized Linux RTX 3060 Ti test: Quantus approximately 218–228 MH/s and Pearl approximately 54–55 TH/s, with accepted pool shares. These stock-setting samples are not a fleet benchmark or Windows hardware certification. Local pool wallet totals and worker attribution can lag miner telemetry.
