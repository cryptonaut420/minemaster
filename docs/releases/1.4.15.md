# MineMaster 1.4.15

- A first file check of a packaged XMRig, Nanominer, or SRBMiner copy reports that it installs on first start, instead of a missing-file error.
- Windows start and stop list managed SRBMiner processes once when none match, accept UTF-16 output, and retry one transient failure. The panel shows a short reason instead of the PowerShell command.
- CPU and GPU stops stay independent. Only a managed SRBMiner whose log path belongs to that slot can be reclaimed.

The accompanying admin labels that packaged state as “packaged, installs on first start.”

SRBMiner 3.7.1, Nanominer 3.10.0 and XMRig 6.26.0 remain pinned. Automated checks use inert downloads, fake processes and disposable data; real Windows installation, policy blocks and GPU faults still need on-site validation.
