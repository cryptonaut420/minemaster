# MineMaster 1.4.18 — KRig reporting reliability

- Recognize KRig pool connection/disconnection events and its startup version. Pool details show the endpoint and original event time.
- Classify KRig failures and warnings correctly in central logs. Statistics API failures are warnings; they do not stop mining or invent readings.
- Keep KRig statistics working through Windows clock corrections using monotonic run-age checks. Frozen or wrong-run responses remain rejected.
- Show when share counters were observed, distinguishing current from last-reported readings in both the desktop and admin. The API exposes the same share quality and declares KRig's 60-second reading freshness window.

Engine versions and existing rig assignments are unchanged. All four pinned engines matched official latest stable releases. Verification: 149 client tests, 145 backend tests, both production builds, and desktop/narrow simulated UI checks. FrontDesk's live KRig API rates and accepted shares matched its logs before this release; longer-term stability and Windows Security behavior remain hardware observations, not guarantees.
