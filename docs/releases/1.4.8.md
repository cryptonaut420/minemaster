# MineMaster 1.4.8

- Detect stalled application downloads after five minutes without transferred bytes, with a two-hour overall limit. Cancel the owned transfer, retain an actionable error, and allow the next scheduled check to retry after cancellation settles. Late completion cannot authorize installation. A download ending without verified completion no longer suppresses all future checks.
- Keep update status notification failures from interrupting update ownership or failed-install cleanup. Explicit installation, target-version checks, Stop cancellation and saved mining intent remain unchanged.
- Report miner file download, verification, extraction, copy and replacement failures separately from launch errors, with the affected path and bounded OS operation name. File errors do not establish an antivirus detection.
- Fail Repair when its final inspection cannot verify the installed files; never report a successful repair for a missing executable.
- Keep Nanominer’s normal startup reboot-policy message out of new error logs; real file-write, pool and fatal errors remain visible.
- Parse Nanominer aggregate share counters, subtracting rejected submissions from its inclusive total and preserving observation times. Rolling summaries and per-device counters remain excluded.

The accompanying admin deployment shows clock/receipt discrepancies in rig details without changing observation timestamps, preserves diagnostic engine identity across engine switches, and labels current-run share rejection alerts with CPU/GPU and the actual engine. Stale share counters no longer trigger current rejection alerts. Direct Play/Pause, fleet totals, history and action toasts remain available.

Engine pins remain SRBMiner-MULTI 3.6.7, Nanominer 3.10.0 and XMRig 6.26.0. Windows Setup/portable and Linux AppImage assets are verified together before publication. No forced fleet update or miner repair is part of this release. Supported clients check/download hourly; installation remains explicit.
