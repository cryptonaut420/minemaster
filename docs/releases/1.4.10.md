# MineMaster 1.4.10

Windows SRBMiner can leave a replacement process alive after its original parent exits. MineMaster now checks for surviving managed instances before launching or repairing, preventing duplicate mining and shared-log truncation. Stop can reclaim an instance only when its executable is under this profile's versioned SRBMiner directory and its command uses this slot's exact log path. Windows PID, creation time, executable and command line are rechecked before termination; unrelated instances are not stopped. Unreadable inventory blocks the operation with a diagnostic.

Controlled update shutdown also checks for these survivors, confirms their exit and preserves their resume intent. Scheduled crash recovery survives an update; a newer explicit Stop cancels captured resume intent. No automatic crash-recovery settings, profiles, clocks or antivirus settings change.

Regression tests use fake processes and mocked Windows inventory. Real Windows recovery is recorded separately in the September 29 audit after rollout. SRBMiner remains 3.7.0, Nanominer 3.10.0 and XMRig 6.26.0.
